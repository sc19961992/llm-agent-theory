# 大语言模型幻觉的推理时计算结构失效：四分类与干预路由

> **状态**：论文大纲
> **日期**：2026-06-09

---

## 摘要（约300字）

当前LLM幻觉研究已有内源/外源、事实性/忠实性、输入/上下文/事实冲突、数据/训练/推理阶段等多种分类，但这些分类多停留在来源层、现象层、根因层或方法层，能够描述输出错在哪里，却较少揭示错误背后的推理时计算结构。本文作为简短综述与概念框架，改从推理时计算结构的两个基本性质出发：**路径依赖**性质推出误差传播和路径缺失，**注意力路由**性质推出容量溢出和注意力漂移。前者解释推理轨迹如何逐步展开并继承早期偏差，后者解释上下文信息如何被承载、选择和定位。本文不把四类视为排他根因，而把它们作为定位主导结构失效的坐标。干预路由是该结构坐标的应用层：重试、拆解、缩短和锚定不是经验技巧清单，而是分别针对推理轨迹、推理编排、上下文负载和注意力定位的基本扰动。

**关键词**：幻觉分类；推理时计算结构；结构失效；误差传播；推理路径缺失；有效上下文；注意力漂移；诊断路由

## 1. 引言

### 1.1 问题：幻觉分类缺乏推理时计算结构视角

- 现有分类综述的局限：Ji et al. (2023, ACM CSUR) 的内源/外源分类、Huang et al. (2025, ACM TOIS) 的事实性/忠实性层级分类、Zhang et al. (2025, Computational Linguistics) 的输入/上下文/事实冲突分类，主要描述幻觉现象或冲突对象；数据/训练/推理三阶段分类则主要停留在生命周期根因层
- 缺乏一个简洁的综述性框架，同时满足两个条件：(a) 每个类别穿透输出现象，对应LLM推理计算中的一个结构环节，(b) 每类结构失效能自然推出一类基本干预，而不是事后把修复方法堆叠到同一个错误标签上

### 1.2 本文的核心主张

在任务目标和前提被良好定义的前提下，且暂不讨论训练诱导的迎合、数据偏差、对抗输入等上游根因，本文主张：

- LLM 的推理时计算结构具有两个基本性质：**路径依赖**与**注意力路由**。
- 路径依赖性质产生两类失效：**误差传播**——本质是路径错误无法纠正，早期偏差沿轨迹继承且不可回滚；**路径缺失**——本质是缺少对应路径，推理编排本身不存在或无法稳定执行。
- 注意力路由性质产生两类失效：**容量溢出**——本质是注意力不足，有效注意力覆盖不及信息负载；**注意力漂移**——本质是注意力指向错误，信息在场但路由落点失准。
- 四类不是排他真因，而是位于现象分类和训练根因分类之间的结构诊断坐标。
- 干预路由不是本文的底层贡献，而是结构分类的应用层外显：哪个最小扰动最先有效，就提示哪个结构环节更可能主导失效。

## 3. LLM 推理时计算结构：两个基本性质如何推出四类失效

本文不先按幻觉表象分类，而先考察 LLM 推理时计算结构的两个基本性质：路径依赖与注意力路由。

### 3.1 基本性质一：路径依赖

LLM 的生成沿 token、思维链、残差状态和注意力路由逐步展开，每步计算以前序输出为条件。这一性质决定了推理轨迹的展开方式，也意味着两种结构风险。

**偏差继承——误差传播（类型1）**：本质是路径错误无法纠正。生成沿轨迹单向展开，已发生的偏差无法回滚修正，只能在其上继续生成，被逐步继承并放大，最终形成整段偏离。

**编排缺失——路径缺失（类型2）**：本质是缺少对应路径。推理路径在权重与层间路由中隐式展开；若某条路径的训练覆盖不足，模型权重中不存在从该类输入到正确输出的稳定编排，即使拥有所有相关事实也无法执行。

### 3.2 基本性质二：注意力路由

LLM 通过自注意力机制在上下文中动态选择和整合信息。这一性质决定了上下文信息的利用方式，也意味着两种结构风险。

**容量约束——容量溢出（类型3）**：本质是注意力不足。有效注意力覆盖范围不及任务所需的信息跨度，标称上下文窗口不等于实际能高质量利用的token数，信息负载超过注意力能同时处理的整合上限。

**定位偏差——注意力漂移（类型4）**：本质是注意力指向错误。注意力在容量范围内但落点失准——受位置偏差、相似干扰和任务焦点变化影响，聚焦于与任务无关或仅表面相似的区域，遗漏关键上下文。

### 3.3 从结构性质到四类失效

| 基本性质 | 失效面 | 结构风险 | 失效模式 | 基本干预 |
|---|---|---|---|---|
| 路径依赖 | 偏差继承 | 路径错误无法纠正——早期偏差不可回滚 | 误差传播 | 重试/低温/截断重采样 |
| 路径依赖 | 编排缺失 | 缺少对应路径——知识存在但无路由编排 | 路径缺失 | 拆解/模板/工具 |
| 注意力路由 | 容量约束 | 注意力不足——信息跨度超过有效注意力覆盖 | 容量溢出 | 缩短/分块/压缩 |
| 注意力路由 | 定位偏差 | 注意力指向错误——信息在场但路由落点失准 | 注意力漂移 | 锚定/前置/标注 |

## 4. 两个基本性质下的四类结构失效模式

### 4.1 路径依赖失效之一：误差传播（Path-Dependence Propagation）

**定义**：推理轨迹中的早期局部偏差进入后续计算，被后续 token 生成、思维链中间结论、残差状态更新或注意力路由继续继承并放大，最终形成整段偏离。

**本质**：路径错误无法纠正。路径依赖意味着生成单向展开、不可回滚——已发生的偏差无法被撤销，后续计算只能在其上继续展开，错误因此被锁定并放大。

**与误差起源的区别**：本类型描述的是**传播/放大机制**，而非偏差为何产生。在路径依赖性质的两个分支中，类型1关注轨迹展开之后的偏差继承——一旦早期偏差进入推理轨迹，后续计算沿其继续展开并放大；类型2关注轨迹展开之前的编排缺失——推理路径本身不存在或无法稳定执行。偏差的起源可能来自注意力路由问题、采样偶然性或错误中间步骤；但类型1的诊断价值在于识别偏差被路径依赖放大的过程，而非追溯偏差的第一来源。

**数学基础**：
路径依赖在 LLM 推理中同时存在于多个计算层级，每一层都意味着偏差一旦进入就不可回滚：

- **Token 级自回归**：$P(x_{1:T}) = \prod_{t=1}^{T} P(x_t \mid x_{1:t-1})$。第t步以完整历史为条件，若第k步产生偏差$\epsilon_k$，后续所有分布被永久改写：$P(x_{k+j} \mid x_{1:k}^* + \epsilon_k, \ldots) \neq P(x_{k+j} \mid x_{1:k+j-1}^*)$。
- **思维链级依赖**：中间结论$c_m$来自前序推理步骤$\{c_1, \ldots, c_{m-1}\}$，早期错误中间结论进入上下文后，后续推理步骤在其上展开，等价于在错误前提上继续推导。
- **残差状态累积**：第$l$层的隐藏状态$h^{(l)} = h^{(l-1)} + \text{FFN}(\text{Attn}(h^{(l-1)}))$。早期层的偏差通过残差连接直通后续所有层，不存在反向修正路径。
- **注意力路由继承**：第$l$层的注意力分布决定信息流向，其路由模式进入残差流后被后续层作为既定事实继承，早期路由偏差同样被锁定。

四层路径依赖的共同结论：生成是单向的，不存在反向修正项——偏差一旦进入轨迹，后续计算只能在已被污染的前缀上继续展开，错误因此被锁定并累积放大（Arora et al., 2022从模仿学习视角给出最坏情况下误差呈二次累积的上界分析）。

**类比**：笔误——不是不会写这个字，只是恰好写错了，但后文可能被这个错误引导偏离主题。

**经验证据**：
- Mekouar (2024, Warwick URSS学生项目)：多模型上观察到幻觉token/sentence的正自相关，温度可能放大该效应；该结果应作为探索性材料而非核心证据
- Zhang et al. (ICML 2024/PMLR)：GPT-4能识别87%的自身幻觉，但早期幻觉产生后后续错误不可避免

**现成案例**：Zhang et al. (ICML 2024/PMLR) 的素数判断案例中，GPT-4先错误声称 9677 不是素数，随后又生成错误解释（如错误因式分解）。论文指出，当把后续错误声明单独拿出来问模型时，模型往往能够识别其错误。这一案例适合展示：首个错误答案会把后续解释推入一致性维护轨道，后续幻觉并不一定来自“完全不知道事实”。

### 4.2 路径依赖失效之二：路径缺失（Missing Reasoning Paths）

**定义**：模型在权重中同时存储语义知识（"是什么"，可通过单步前向传播提取，训练数据覆盖广）和推理路径（"怎么推"，需多步隐含展开，训练数据覆盖密度低）。若某条推理路径在训练数据中覆盖不足或完全缺失，模型在该路径上无正确程序可执行，输出等效于胡言乱语。

**本质**：缺少对应路径。模型权重中不存在从该类输入到正确输出的稳定编排——不是缺少子知识，而是缺少将这些子知识串联为有效推理的路由序列。

**关键区分**：这不是"不知道事实"——模型可能拥有所有相关事实。这是"不知道怎么把这些事实串联成一个有效推理"。

**数学基础**：
- 前馈层（FFN/MLP）存储可跨样本泛化的语义知识——经过预训练，模型参数中编码了词语间的概念关联、事实三元组等信息（Geva et al., 2021；Meng et al., 2022）
- 自注意力机制执行上下文路由——每层根据当前隐藏状态动态计算信息流向，决定哪些token的信息被聚合到当前位置
- 多步推理需要L层中注意力路由的特定序列编排——若某条推理路径对应的路由模式在训练数据中从未出现过，即使FFN中存储了所有需要的子知识，注意力也无法正确编排它们（Brinkmann et al., ACL 2024）

**类比**：学生知道所有概念定义与公式定理，但没学过这类题型的解题路径。

**经验证据**：
- "Reversal Curse" (Berglund et al., ICLR 2024; arXiv 2023)：GPT-4正向79%，反向33%
- "Alice in Wonderland" (Nezhurina et al., 2024, arXiv预印本)：顶尖模型在简单组合推理任务上出现严重崩溃
- Li et al. (LREC-COLING 2024)：程序性知识仅在简单逻辑任务中有效

**现成案例**：Berglund et al. (ICLR 2024) 的 Reversal Curse 显示，模型学到或知道“A is B”并不自动意味着能稳定回答“B is A”。例如，GPT-4对“Tom Cruise 的母亲是谁”回答正确率远高于反向问题“Mary Lee Pfeiffer 的儿子是谁”。该案例适合展示：事实关联可能存在，但反向检索/推理路径没有被可靠编排。

### 4.3 注意力路由失效之一：容量溢出（Capacity Overflow）

**定义**：有效上下文（注意力实际能高质量聚焦的token范围，通常10K–200K）远小于标称最大上下文（可达1000K）。当任务所需信息跨度超过有效上下文时，关键信息超过注意力覆盖能力，任务无法被可靠完成。

**本质**：注意力不足。有效注意力覆盖范围不及任务所需的信息跨度——不是上下文窗口装不下，而是注意力没有足够的能力同时高质量处理这么多token。

**有效上下文 vs 最大上下文**：
- 最大上下文：架构层面可接受的token上限（由位置编码、KV缓存等硬约束决定）
- 有效上下文：功能层面注意力能**有意义地利用**的token范围（由注意力稀释、位置衰减等软约束决定）
- 经验发现（Paulsen, 2026; arXiv 2025）：MECW可能远小于MCW，在某些设置下可低至标称上下文窗口的一小部分

**类比**：一本书有1000页，但你真正能有效精读的只有100页，中间900页只是翻过。

**经验证据**：
- Liu et al. (TACL 2024; arXiv 2023)：长上下文利用呈现位置依赖，关键信息位于中间位置时性能下降
- Ebrahimzadeh & Salili (2026, arXiv预印本)：更长上下文在信息稀释时可能降低而非提升准确率

**现成案例**：可用 Paulsen (2026) 的“最大有效上下文窗口”（Maximum Effective Context Window, MECW）作为容量溢出的近邻案例：模型虽然拥有较大的标称上下文窗口，但在真实任务中能稳定、有效利用的信息范围可能显著更小，因此当任务需要跨越过多文档、段落或证据片段时，错误并不一定来自单个关键信息被放错位置，而是来自一次推理中需要整合的信息量超过了有效窗口。Ebrahimzadeh & Salili (2026, arXiv预印本) 进一步展示，长上下文中的事实分布和信息稀释会影响字面抽取、逻辑推理与幻觉风险，说明“给更多上下文”不必然提升可靠性。这里的案例不是一个完全干净的单任务失败样本，但足以说明类型3的诊断要点：若分块、压缩或局部检索后输出改善，优先怀疑容量溢出而非注意力漂移。

### 4.4 注意力路由失效之二：注意力漂移（Attention Drift）

**定义**：即使任务复杂度在有效上下文容量之内，注意力也未必自动落在正确的信息区间。自注意力没有内建的"应该聚焦何处"的保证——它受位置偏差（首因/近因效应）、内容相似度干扰（语义相近但不相关的文本块在注意力竞争中胜出）、以及缺乏显式检索路由的影响，可能聚焦于无关区域而遗漏关键上下文。

**本质**：注意力指向错误。注意力在容量范围内但落点失准——不是注意力不够用，而是注意力用错了地方，聚焦于与任务无关或仅表面相似的区域。

**与类型3的关键区别**：
- 类型3：注意力不足（"装不下"）
- 类型4：注意力指向错误（"看错地方"）

**类比**：还是那本1000页的书，你看了100页，但是没看目录，走神了没把握到精髓，读完不知道刚才读了什么。

**经验证据**：
- Liu et al. (TACL 2024; arXiv 2023)："Lost in the Middle"效应——关键信息在中间位置时检索准确率显著低于两端
- Chuang et al. (2024)：注意力回看率（lookback ratio）下降是上下文幻觉的实时预测信号
- Hsieh et al. (Findings ACL 2024)：校准位置注意力偏差可改善长上下文利用
- An et al. (NeurIPS 2024)：IN²训练通过信息密集型长上下文QA修复注意力覆盖，效果显著

**现成案例**：Liu et al. (TACL 2024; arXiv 2023) 的多文档问答与 key-value 检索实验显示，当相关信息放在上下文开头或结尾时模型表现较好，而放在中间位置时明显下降。该案例适合展示：信息其实在输入中，也未必超过标称窗口，但模型没有稳定定位到正确位置。

### 4.5 两层分类总览

| 基本性质 | # | 类型 | 结构环节 | 失效机制 | 基本干预 |
|---|---|------|---------|---------|------|
| 路径依赖 | 1 | 误差传播 | 推理轨迹 | 路径错误无法纠正——早期偏差不可回滚，被后续计算继承放大 | 重试/低温/截断重采样 |
| 路径依赖 | 2 | 路径缺失 | 隐式推理编排 | 缺少对应路径——知识存在但路由编排缺失，推理无法稳定执行 | 拆解/模板/工具 |
| 注意力路由 | 3 | 容量溢出 | 上下文整合 | 注意力不足——信息跨度超过有效注意力覆盖范围 | 缩短/分块/压缩 |
| 注意力路由 | 4 | 注意力漂移 | 注意力定位 | 注意力指向错误——信息在场但路由落点失准 | 锚定/前置/标注 |

## 5. 区分、重叠与边界

### 5.1 区分标准的目标

作为推理时结构失效框架，本文不要求每个幻觉实例都存在可观测、排他的因果来源。更实际的目标是：在给定任务和输入后，识别最可能主导输出错误的计算结构环节，并说明哪类低成本干预最值得优先尝试。因此，下列标准应被理解为**主导结构失效的启发式判据**，而不是完整因果定论。

### 5.2 主导结构失效的启发式判据

**第一层：先判定基本性质。**

- 重试、回滚、拆解、模板化有效：优先看作**路径依赖问题**。
- 缩短、分块、压缩、前置、标注有效：优先看作**注意力路由问题**。

**第二层：再判定具体失效。**

**提示类型1（误差传播，本质：路径错误无法纠正）**：模型大体具备完成任务所需的知识、上下文和推理路径，但在某个早期 token、中间步骤或注意力定位上出现局部偏差，该偏差沿单向轨迹被锁定并放大，后续输出无法回滚修正。

- 诊断信号：同一输入下重新生成、降低温度，或在偏离发生前截断/回滚并重新生成后，输出有较高概率回到正确轨道
- 区分重点：错误表现出明显的偶然性和路径锁定特征——偏差一旦发生就无法自行纠正，但重新采样可避开

**提示类型2（路径缺失，本质：缺少对应路径）**：相关事实已经给定或可由模型调用，输入长度也未明显超过有效上下文范围，但模型权重中不存在从该输入到正确输出的稳定路由编排，在从前提到结论的推理中稳定出错。

- 诊断信号：多次独立采样出现相似错误；提供中间步骤、形式化模板或子问题拆解后，输出明显改善
- 区分重点：问题不主要在“有没有信息”，而在“权重中是否已编码了可执行该推理的路由序列”

**提示类型3（容量溢出，本质：注意力不足）**：任务所需信息跨度、文档数量或干扰规模超过注意力的有效覆盖能力，导致关键信息虽然位于输入中，却无法被同时高质量处理。

- 诊断信号：分块处理、摘要压缩或局部检索后，输出明显改善
- 区分重点：改善来自减少一次推理中注意力必须同时覆盖的信息量，而不是单纯改变关键信息位置

**提示类型4（注意力漂移，本质：注意力指向错误）**：关键信息位于有效上下文范围内，任务也未明显超过模型能力，但注意力的落点失准——稳定地聚焦于错误区域或被相似但无关的信息干扰。

- 诊断信号：在基本保持输入信息量的前提下，将关键信息前置、后置、重复或显式标记后，输出明显改善
- 区分重点：问题不在“装不下”，而在“看错地方”；因此最好用保持长度和信息量基本不变的锚定干预来检验

### 5.3 重叠关系

四类结构失效在真实样本中可能并发。路径依赖问题和注意力路由问题也会互相触发：例如注意力漂移先选错证据，随后错误中间结论进入推理轨迹并被误差传播放大。因此，本文采用**主导结构失效**而非排他真因作为分类单位：先看主导性质是路径依赖还是注意力路由，再看具体是四个分支中的哪一个。

---

### 5.4 边界条件与未覆盖情形

**适用边界：**

本框架主要适用于文本推理场景中的推理时系统性失效，适用范围受以下条件约束：
- 任务目标和评价标准相对明确，至少存在可判断的正确/不正确输出
- 输入不是蓄意对抗样本，也不以越狱、提示注入或安全规避为主要场景
- 暂不把训练数据投毒、错误标注、RLHF迎合、不确定性压制、工具调用失败等上游根因直接纳入四类结构失效
- 关注模型在已有输入和参数条件下如何失败，而非训练阶段为什么形成这些失败倾向

**框架覆盖的推理链条：**

在上述边界内，四类结构失效覆盖了模型推理链条中的两个基本性质和四个关键位置：
- 路径依赖性质：路径错误无法纠正（类型1）与缺少对应路径（类型2）
- 注意力路由性质：注意力不足（类型3）与注意力指向错误（类型4）

这里的“覆盖”应理解为综述性覆盖：它说明常见缓解策略和已有文献现象大多可被映射到这两个基本性质和四个位置，而不是形式化地排除其他机制。

**可能遗漏的类型及处理方式：**

**Q1：知识冲突（权重先验与上下文事实冲突）→ 是否构成独立类型？**
- 处理：若任务已明确要求以上下文为准，而模型仍选择权重先验，可作为类型4的一个常见表现；若上下文权威性本身不明确，则属于任务定义问题
- 结论：在本文框架中作为边界情形处理，不单列为第五类

**Q2：组合组装失败（子路径存在但组合为新推理链时出错）→ 是否构成独立类型？**
- 处理：子路径存在但组合失败，本质上仍属于推理路径编排不稳定，可归入类型2的扩展情形
- 结论：在简短框架中暂不细分，后续可进一步拆成“路径缺失”和“路径组合失败”

**Q3：校准性解码错误（非小概率token，而是logits本身指向错误方向）→ 是否构成独立类型？**
- 处理：若错误方向在多次采样中稳定出现，更接近类型2或上游知识错误；若正确分布存在但局部选择偏离并被放大，则更接近类型1
- 结论：作为类型1与类型2之间的边界情形处理

**Q4：检索或工具链错误 → 是否属于四类结构失效？**
- 处理：若外部检索返回错误材料，根因在工具链或数据源，不属于模型内部推理时失效；若材料正确但模型没有使用好，则可落入类型3或类型4
- 结论：需要在应用场景中显式区分“模型幻觉”和“外部系统错误”

**小结：**

因此，本文框架的价值不在于声称覆盖所有幻觉根因，而在于提供一个足够小、足够可用的推理时结构地图：先看路径依赖还是注意力路由，再看是路径错误无法纠正、缺少对应路径、注意力不足还是注意力指向错误，并允许读者在边界情形中采用“主导结构失效 + 次要线索”的复合描述。

## 6. 基本干预路由：最小成本诊断树

上述四类结构失效的直接应用不是构建复杂的内部状态监测系统，而是把每一类结构环节转化为一个更基本的最小扰动：重试扰动推理轨迹，拆解扰动推理编排，缩短扰动上下文负载，锚定扰动注意力定位。由此得到一个任何用户都能立即使用的**启发式诊断树**。它的意义不只是选择修复工具，而是用最小干预把表面幻觉背后的结构环节显影出来。核心原则只有一条：

> **不以内部指标作为前提，而以干预反馈进行路由。哪个手段首先有效，就把它作为优先修复动作，并提示相应结构失效可能参与其中。**

### 6.1 四类结构失效与基本干预

| 基本性质 | 观察到的症状 | 基本干预 | 对应结构失效 | 推荐缓解 |
|---|---|---|---|---|
| 路径依赖 | 同一问题重答后明显改善；错误解释依赖先前错误答案（路径错误无法纠正） | 重试/低温/截断重采样 | 类型1：误差传播 | 多样化采样后投票、早期答案校验、对比解码 |
| 路径依赖 | 多次重答都犯同类推理错误；给出中间步骤或模板后改善（缺少对应路径） | 拆解/模板/工具 | 类型2：路径缺失 | CoT、程序化推理、外部工具、任务模板化 |
| 注意力路由 | 输入很长、多文档、多约束；分块或摘要后改善（注意力不足） | 缩短/分块/压缩 | 类型3：容量溢出 | RAG召回压缩、层级摘要、map-reduce式综合 |
| 注意力路由 | 信息在输入中但被忽略；前置/高亮/重复后改善（注意力指向错误） | 锚定/前置/标注 | 类型4：注意力漂移 | 证据前置、引用锚点、位置校准提示 |

### 6.2 诊断树：四步递增成本试探

发现模型输出有问题后，按以下顺序依次尝试。成本从低到高排列——每一步的成本都比"从一开始就全上"的做法低得多，也避免了"用RAG修笔误"式的错配浪费。需要强调的是，这个流程识别的是**优先有效干预及其对应的主导结构失效**，而不是对完整因果链的最终判决。

```
发现幻觉
  │
  ├─ 第一步：重新生成（成本：1次推理）
  │   同一输入再问一次。
  │   ├─ 恢复正常 → 基本性质：路径依赖；优先干预：重试/低温；线索：误差传播。完成。
  │   └─ 仍然错误 → 重试不是优先有效干预，继续。
  │
  ├─ 第二步：拆解步骤（成本：添加"请逐步推理"）
  │   要求模型给出中间步骤。不加任何新信息。
  │   ├─ 恢复正常 → 基本性质：路径依赖；优先干预：拆解/模板化；线索：路径缺失。
  │   │               CoT已将长程推理路径拆为模型已知的短程子步骤。
  │   └─ 仍然错误 → 拆解不是优先有效干预，继续。
  │
  ├─ 第三步：缩短输入（成本：截断上下文 + 1次推理）
  │   尽量保持任务信息完整，但通过分块、压缩或局部检索降低单次负载。
  │   ├─ 恢复正常 → 基本性质：注意力路由；优先干预：分块/压缩；线索：容量溢出。信息在完整时太多，
  │   │               截断/分块后每段在有效上下文范围内。
  │   └─ 仍然错误 → 分块/压缩不是优先有效干预，继续。
  │
  └─ 第四步：锚定关键信息（成本：修改提示词 + 1次推理）
      将关键信息移到开头或结尾，或显式标记（"请注意以下内容：……"）。
      ├─ 恢复正常 → 基本性质：注意力路由；优先干预：锚定/高亮；线索：注意力漂移。信息一直在，但模型一直在看别处。
      └─ 仍然错误 → 超出本框架的简化诊断范围
                     → 可能原因：权重中编码了错误知识、任务本身无解、
                        或为上游根因（训练数据错误/对齐偏差）
```

### 6.3 为什么这个顺序

| 步骤 | 成本 | 逻辑 |
|------|:---:|------|
| 重新生成 | 极低 | 先排查路径依赖中的偶然轨迹偏差 |
| 拆解步骤 | 低 | 继续排查路径依赖是否缺少稳定编排 |
| 缩短输入 | 中 | 转向注意力路由，先降低上下文负载 |
| 锚定信息 | 极低/单次 | 再检查信息在容量内但定位失败的情况 |

关键洞察：**诊断和修复可以同步推进。** 哪一步恢复了正确输出，该步就给出了一个可操作的类型提示和一条可复用的修复路径。不需要一个完全独立的"先诊断、再开方"阶段。

### 6.4 诊断树 vs. 当前通行做法

当前用户面对幻觉的典型反应：
- 反复重新生成（假设一切是类型1）
- 同时加CoT+RAG+分块（不区分类型，成本堆叠）
- 放弃，认为"模型不行"

诊断树把"碰运气"变成了"按顺序排查"——每次只加最少的干预，用反馈来导航。它近似于一个**输入空间中的逐步分流过程**：先排查路径依赖问题，再排查注意力路由问题；在每个基本性质内部再区分两个失效分支。

### 6.5 自动化潜力

上述流程目前以手动方式实现，但其核心逻辑可被封装为一个轻量包装层：

- **无需访问模型内部状态**：不读logits、不读注意力权重、不标定MECW
- **只比对输出**：原始输出 vs. 带干预的输出，正确与否由用户确认或校验函数判定
- **干预模板预置**：四种干预对应四个标准化的提示词变换
- **学习型路由**：积累足够的诊断-干预配对后，可通过简单分类器跳过试探步骤，直接从输入特征预测干预类型

这一路线的关键优势：对API-only模型适用，干预模板跨模型迁移，不依赖任何模型内部信息。

## 7. 讨论

### 7.1 诊断树的局限与扩展方向

- 第四步失败后的"超出分类范围"路径需要更细化的处理——目前退化为人工判断
- 多类型并发（如类型2+类型4同时存在）时单步修复不足以完全恢复，需要组合干预
- 诊断树的深度（4步）可随分类细化而扩展，但成本递增原则不变
- 可与RL-based路由器集成——将诊断树的选择逻辑训练为策略；相近方向可参考 Router-R1 (Zhang et al., 2025, arXiv预印本) 对多轮路由与聚合策略的强化学习训练

### 7.2 与现有缓解策略的映射

现有常见缓解策略在两个基本性质中的位置：
- 路径依赖：重试/对比解码 → 类型1；CoT/模板/工具 → 类型2
- 注意力路由：分块/RAG压缩 → 类型3；证据前置/注意力校准 → 类型4
- 跨性质策略：RAG 可能同时缓解类型2（外挂知识/路径）和类型3（缩小上下文）

多数缓解策略都可在此框架中找到一个主要靶向性质；同一策略也可能同时作用于多个分支。这从侧面说明该框架具有操作性，但不构成对覆盖范围的形式化保证。

### 7.3 未来研究入口：路由独立性假说

本节只提出一个后续研究入口，不作为本文框架成立的前提。两个基本性质下的四个失效分支共同提示一个可能的底层问题：这些失败也许部分共享同一个结构条件，而非四个完全独立的缺陷。

当前Transformer中，注意力路由寄生在语义参数和语义表征之上：路由所需的QK匹配信号从同一个token表征向量中读取，该向量同时也服务于FFN的语义变换；路由本身没有独立的可训练参数——W_Q和W_K属于语义参数空间，训练时被语义目标的梯度主导更新；生成阶段也缺少路由层面的反馈监控。与知识存储和生成轨迹相比，路由层更缺少“自己的东西”：独立参数、独立表征空间和独立反馈回路。

在这一假说下，四种幻觉可被看作同一结构状况的不同出口。现有文献在若干出口各自做了局部缓解（如 Zou et al., ICML 2025 在多模态幻觉中提出 memory-space visual retracing；Guo & Chen, 2025 以预印本形式提出知识/推理解耦架构；Hsieh et al., Findings ACL 2024 讨论位置注意力校准），但尚未有工作系统地把"路由的参数独立性和表征独立性"作为正面架构问题处理。由于这一判断仍属推测，本文仅将其放在讨论末尾，作为未来工作的入口。

这引出两个承接性问题——本文不回答，但它们是后续工作的起点：

- **如果给路由一个独立于语义的表征子空间（在残差流中拆分出专属于路由的向量维度，不被语义变换污染），上述四种失效中有几种会在不依赖任何校准或训练干预的情况下自行消退？**

- **如果路由拥有可训练的策略参数（独立于FFN权重、有自己的学习目标和更新速度），推理路径缺失能否从一个训练覆盖问题转化为一个参数容量问题——即从"数据中没见过这条路径"变为"参数还没学会这条路"？**

## 8. 结论

本文提出了一个面向LLM系统性幻觉的推理时计算结构失效框架。框架从推理时计算结构的两个基本性质出发：路径依赖和注意力路由；再在每个性质下区分两个失效分支：路径依赖产生误差传播和路径缺失，注意力路由产生容量溢出和注意力漂移。基于该结构分类，本文提出最小成本诊断树，以递增成本的简单干预（重试→拆解→缩短→锚定）替代无差别堆叠策略；这些干预不是外加的修复技巧，而是对两个基本性质、四个分支的基本扰动，用于识别优先有效干预并反推主导结构失效。该框架的价值不在于覆盖所有幻觉根因，而在于为用户和研究者提供一个位于现象分类和训练根因分类之间的结构地图。

诊断路由是这一结构地图的应用层外显，而不是本文唯一贡献。重试和拆解对应路径依赖性质，缩短和锚定对应注意力路由性质。至于注意力路由是否需要更独立的参数、表征和反馈回路，本文只将其作为讨论末尾的未来研究入口，而不作为本文框架的结论性主张。

## 附录A：诊断树伪代码

```python
def diagnose_and_fix(model, prompt, verify_fn):
    """最小成本诊断树。verify_fn 可以是用户确认或自动校验函数。"""
    
    # Step 1: 重试 — 推理路径 / 类型1（误差传播）
    output = model.generate(prompt)
    if verify_fn(output):
        return output, "OK"
    output2 = model.generate(prompt)  # 不做任何修改，直接重新生成
    if verify_fn(output2):
        return output2, "基本性质：路径依赖；优先干预：重试/低温；线索：误差传播"
    
    # Step 2: 拆解 — 推理路径 / 类型2（路径缺失）
    prompt_cot = prompt + "\n请逐步推理，给出中间步骤。"
    output3 = model.generate(prompt_cot)
    if verify_fn(output3):
        return output3, "基本性质：路径依赖；优先干预：拆解/模板化；线索：路径缺失"
    
    # Step 3: 缩短 — 注意力路由 / 类型3（容量溢出）
    chunks = split_into_chunks(prompt, chunk_size=MAX_SAFE_TOKENS)
    partial_results = [model.generate(c) for c in chunks]
    prompt_aggregate = f"根据以下分段结果综合回答：\n" + "\n---\n".join(partial_results)
    output4 = model.generate(prompt_aggregate)
    if verify_fn(output4):
        return output4, "基本性质：注意力路由；优先干预：分块/压缩；线索：容量溢出"
    
    # Step 4: 锚定 — 注意力路由 / 类型4（注意力漂移）
    # 将关键约束/信息移到prompt最开头
    prompt_anchored = extract_key_info(prompt) + "\n\n---\n\n" + prompt + "\n\n请注意上述关键信息。"
    output5 = model.generate(prompt_anchored)
    if verify_fn(output5):
        return output5, "基本性质：注意力路由；优先干预：锚定/高亮；线索：注意力漂移"
    
    # 超出简化诊断范围
    return output, "超出简化诊断范围（可能为权重知识错误、任务无解或上游根因）"
```

成本分析：最坏情况5次推理（1次原始+4次试探），最好情况2次（重复生成成功）。所有步骤均不需要读取模型内部状态。

## 附录C：幻觉自检 Skill

将以下提示词放入 Agent 系统提示中即可生效：

```
# 幻觉自检

当你准备输出时，如果对正确性有疑虑，按此顺序自检。先查路径依赖，再查注意力路由，每次只试一步：

1. 重答：直接重新生成一次。如果结果变了 → 路径错误无法纠正（早期偏差被带偏）。
2. 拆解：先列出解题步骤，再按步骤写答案。如果通了 → 缺少对应路径（推理编排不稳定）。
3. 缩上下：压缩或分块输入，降低一次性上下文负载。如果通了 → 注意力不足（容量溢出）。
4. 锚关键：把关键信息摘出来放在最前面，再读一遍。如果通了 → 注意力指向错误（定位失败）。

四步都不通 → 诚实告诉用户"这个我不确定"。
```
